# AI 机会研究台

面向公开信息的需求发现与机会评估平台。支持多源采集、数据清洗、机会识别、主题聚类、价值排序和立项策划，所有结果均可追溯至所属批次与来源记录。

**[进入网站](https://drinkwater10086.github.io/opportunity-app/)** · [使用说明书](USER_GUIDE.md) · [数据来源](SOURCES.md)

## 开始使用

1. 打开网站，点击 **新建采集批次**。
2. 填写需求方向和检索词，选择数据来源、采集上限与时间窗口，点击 **采集公开数据**。
3. 采集完成后点击 **进入程序分析**，保留默认参数并开始分析。
4. 查看分析结论、机会主题、价值排序和原文证据。
5. 点击 **核对提交文件**，查看字段和编号检查结果；编辑立项策划，下载四份 CSV、分析记录 JSON 和策划 Markdown。

每次发起采集创建独立批次；同批次可以保存多次分析记录，便于调整参数和比较结果。各批次独立处理，历史记录保留。

单次程序分析支持最多5000条记录、清洗正文合计5000万字符；完整保留原文，不截断输入。部分来源失败时，可复制完整成功来源创建可分析的新批次。

## 主要功能

| 功能 | 内容 |
|---|---|
| 多源采集 | 分组检索、自动分页、时间筛选、来源状态与部分成功恢复 |
| 数据清洗 | 文本格式统一、记录去重、隐私字段处理和原始资料留存 |
| 内容筛查 | 采集时识别招聘、求职及推广；保留原文和隔离依据，排除项不进入机会聚类 |
| 机会识别 | 方向匹配、业务任务与技术故障区分、多段证据整理、功能与行业分类 |
| 主题聚类 | TF-IDF、LSA及可选E5向量；支持统一聚类或按功能分组后聚类 |
| 价值评估 | 来源覆盖与记录规模加权排序、同分提示、权重及来源依赖分析 |
| 立项策划 | 八项策划内容、修订记录及Markdown导出 |
| 质量评价 | 编号完整性、轮廓系数、分析对比ARI、候选重合率、提交文件核对和运行耗时 |
| 团队协作 | 标准部署支持管理员、研究员和决策者角色 |

## 本地分析功能

采集清洗阶段提前检查内容类型，招聘、求职和推广记录在后续判别中直接作为非机会；完整记录仍保留在result1、result2。可在页面查看隔离数量及原文依据，见[采集内容筛查](COLLECTION_SCREENING.md)。

主题卡片提供需求摘要，按原记录整理用户场景、需求问题、当前做法、流程短板、发生频率和技术线索。长文可查看多段有效证据，各段保留原文位置。

需求判别区分关闭AI功能、已有方案介绍、安全风险讨论、设想性方案与未解决业务诉求。具体任务优先用于分类；聚类后检查明确任务冲突。已有批次可直接重新分析，使用原采集记录生成新的分析历史，无需重新采集。

“设置下一次分析参数”中可选择分层聚类和语义扩展线索。扩展线索与正式机会分开展示。程序使用有容量控制的进程缓存复用规则判别与向量计算，重复分析时显示缓存命中情况。功能与默认设置见[本地分析说明](ANALYSIS_UPGRADE.md)。

## 采集数量怎么设置

采集数量可手动输入 **1–500之间的整数**，默认100。这个值是**每个来源选项、每组检索词**的采集上限；页面同步显示合计上限。

例如4个来源选项、3组检索词、每组100条，合计上限为1200条。实际保留量受匹配结果、时间窗口、分页配额、来源自身上限和去重影响。Product Hunt每组最多8项；RSS和最新主题流按当前可用内容返回。

## 数据来源

目前启用 **13个平台、14个采集选项**：

- GitHub（项目简介、Issues主帖）
- Stack Overflow、Super User、The Workplace
- Hacker News、Node-RED、V2EX
- arXiv、IT之家、InfoQ中国、量子位
- Kaggle、Product Hunt

赛事附件20个平台中，已有8个平台接入。来源目录提供各平台状态、内容范围及接入条件；未接入来源的处理步骤见[来源接入说明](SOURCE_AUTH_GUIDE.md)。各适配器按公开接口、订阅范围及平台许可获取数据，详细字段见[来源说明](SOURCES.md)。

GitHub采集自动复用后端主机已有的Git登录，始终限定公开仓库和公开Issue。无需在网页填写凭据；令牌仅在后端内存中用于官方搜索接口，不进入导出文件。未登录时使用匿名搜索。遇到短期限流，按响应头等待并有限重试；长时间限流保留已采集页面并提示稍后重试。

## 分析与结果

处理链路为：结构化清洗 → 规则判别 → 标签分类 → 文本向量 → 层次聚类 → 加权评分 → 策划整理。

机会证据分衡量条件匹配程度，主题价值分用于同批次相对排序。轮廓系数衡量分组结构，ARI衡量两次分组的一致性。指标定义和计算条件见[分析方法](LOCAL_ANALYSIS.md)和[价值评分](VALUE_DIAGNOSTICS.md)。

## 在线部署

GitHub Pages提供固定入口，Python后端与数据库由项目主机运行，通过HTTPS通道对外服务。访问网站时，项目主机和通道需保持在线；通道地址变更后，更新`docs/index.html`并通过Git发布。

当前在线工作区供团队共享使用。标准账号版支持角色权限；数据库、采集正文、访问口令和运行日志不提交到公开仓库。

## 维护与运行

需要Python 3.12。在仓库目录执行：

```powershell
python -m pip install -r requirements.txt
python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

打开`http://127.0.0.1:8000`，首次运行创建管理员账号。数据库位于`data/`。测试依赖见`requirements-dev.txt`，测试命令：

```powershell
python -m pytest -q
```

系统采用Web应用形式，用户通过浏览器完成操作。运行、部署与版本管理步骤见[使用说明书](USER_GUIDE.md)。
